# Mac 用户详细操作手册

适用项目：VideoWorkbench / VIDEOPILOT 全自动视频工作台

核对日期：2026-09-07；依据：主分支 `6e0f0c6` 的启动脚本、课程页面、配置代码和同步助手。

本手册不要求日常使用 Codex。第一次本地安装需要终端操作；系统权限、Mac 剪映兼容性仍需在用户电脑上验收。

## 一、先选对路线

| 你的情况 | 使用路线 | Mac 负责什么 |
| --- | --- | --- |
| 只有仓库，没有服务器网址 | A：本地试用 | 分析、剪辑、运行工作台和剪映 |
| 管理员给了 HTTPS 网址、访问方法和适配电脑的助手包 | B：服务器模式 | 浏览器操作、接收草稿、剪映继续编辑 |
| 只有同步助手 ZIP，没有服务器 | 暂不能使用 B | 助手不是完整剪辑软件，不能独立学习课程或渲染 |

当前代码已包含课程计划和 Mac 图形设置入口，Mac/Windows CI 构建与启动契约有通过记录；**真实 Mac 的安装、自启、剪映时间线，真实钉钉长课程与公网部署仍需对应资源验收**。未签名开发构建不能当作普通用户无警告安装的正式产品。

没有服务器就先按 A 操作，不必先申请配对码。B 必须等管理员部署和验收后再使用。

### 不要弄错地址

- A 默认地址：`http://127.0.0.1:8130`。`127.0.0.1` 指你自己的 Mac。
- 聊天里出现过的 `8177` 是维护者 Windows 的临时验收端口，不是 Mac 默认端口。复制维护者的任务链接不会把视频带到你的电脑。
- B 用管理员提供的真实 HTTPS 网址；`https://video.example.com` 只是示例，不是现成服务。
- Mac 启动脚本固定使用 8130，不会自动避让占用端口。

## 二、开始前准备什么

1. 苹果菜单 →“关于本机”，记录芯片和 macOS 版本。优先 Apple Silicon（M 系列）；Intel 用户不能直接使用未声明兼容的 ARM 安装包。当前助手包不是 Universal 包。
2. 准备稳定网络、可用磁盘空间。首次需要下载 Python、依赖和模型；不需要 Key 不等于首次可以离线安装。源视频、成片和剪映媒体副本都会占空间。
3. 从[剪映专业版官网](https://www.jianying.com/web/professional)选择 Mac 下载项，按官方安装器操作。不要从陌生网盘下载修改版。
4. 手动打开一次剪映，完成必要的系统确认，创建一个空草稿并返回首页，让客户端建立目录。首轮先保留默认草稿位置。
5. 准备一小段清楚讲解剪辑要求的教程，以及两三条实际要剪的视频。先测短片，不从几小时大课开始；耗时取决于机器、网络和素材，不能承诺固定分钟数。

**教程和素材不是一回事：**教程用于学习“怎么剪”，配套素材才是剪入成片的画面。购买网课不自动获得素材商用权；没有商业授权就先做个人学习验证。

## 三、A 路线：Mac 本地安装与启动

### A1. 打开终端，准备 Git 与 Homebrew

按 `Command + 空格`，输入“终端”并打开。每个代码块可单独复制执行，再按回车。

```bash
git --version
```

如果 macOS 提示安装命令行开发工具，按系统提示完成后再执行。也可以用下面的命令发起官方安装：

```bash
xcode-select --install
```

检查 Homebrew：

```bash
brew --version
```

没有时，打开 [Homebrew 官方安装说明](https://docs.brew.sh/Installation)，按官方页面安装，并执行安装器最后的 **Next steps**，然后打开新终端。Homebrew 用于准备 FFmpeg；A 不要求 Docker Desktop 或完整 Xcode IDE。

安装器要求 Mac 登录密码时，由本人在终端输入；不显示字符是正常的。不要把密码发到聊天里。

已装 Homebrew 但命令找不到：Apple Silicon 常见位置为 `/opt/homebrew/bin/brew`，Intel 为 `/usr/local/bin/brew`。按安装器 Next steps 修复 PATH，不要重复装两套。

### A2. 下载代码

以下命令把项目放在当前用户的 Projects 目录，不需要 B 盘/C 盘：

```bash
mkdir -p "$HOME/Projects"
cd "$HOME/Projects"
git clone https://github.com/BreetyGreen/video-workbench.git
cd video-workbench
```

若提示目录已经存在，不要删除；进入已有目录，先看 `git status --short`，更新方法见第八节。公开仓库通常无需 GitHub 登录，不要把个人令牌拼进克隆 URL。

### A3. 首次安装并启动

在 `video-workbench` 目录执行：

```bash
bash scripts/bootstrap.sh
```

脚本准备 Python 3.12、uv、锁定依赖，检查/安装 FFmpeg 与 FFprobe，创建用户数据目录并启动服务。首次下载可能较慢，不要同时开多个终端反复启动。

**成功标志：**出现 `VideoWorkbench is ready at http://127.0.0.1:8130/` 或 `already running`，并打开浏览器。

没有自动打开时，手工访问：

- [工作台](http://127.0.0.1:8130/)
- [配置助手](http://127.0.0.1:8130/setup)
- [课程自动剪辑](http://127.0.0.1:8130/courses)

服务运行后这些地址才有效；双击仓库里的 HTML 文件不能替代启动。

### A4. 首次引导，先不要配所有 Key

1. 选择“先直接创作”，或进入“配置助手”。
2. 确认 FFmpeg、FFprobe 和运行目录可用。
3. 看“剪映交付”是否发现客户端与草稿目录。未发现不阻止生成 MP4，但会影响自动导入。
4. Dify、火山、抖音等显示“未配置”不等于本地模式失败。
5. 进入“课程自动剪辑”，按第四节先做一次手动任务。

第一次转写/OCR可能下载模型；当前本地默认使用 CPU，不承诺 GPU 加速。没有 TTS 时保留原声，不会凭空生成高质量讲解旁白；没有人声也不能保证有可用字幕。

## 四、上传教程，剪出第一条视频（A/B 共用）

### 1. 导入教程和配套素材

打开侧栏“课程自动剪辑”，展开 **“1. 导入教程和配套素材”**。

| 字段 | 如何填写 |
| --- | --- |
| 课程名称 | 例如“帽子商品短视频课—第一课” |
| 教学文件（视频或 TXT 讲义） | 老师讲解视频或真实 TXT 讲义；首轮建议一份，不把商品素材放这里 |
| 用于剪辑的配套视频 | 实际商品、人物、场景视频，可以多选 |
| 素材使用权 | 个人练习选“仅限个人学习”；确有商业授权才选“已取得商业使用授权” |
| 权利确认 | 确认有权上传和处理后勾选 |

点击 **“导入课程”**，等待课程出现在下拉列表。此页面不把 PDF、PPT、ZIP 承诺为完整教学解析入口。课程接口默认单文件上限 500 MiB，服务器还可能有更低上传限制；过大时按课节拆分或联系管理员，不能只改后缀。

### 2. 保存手动计划

在 **“2. 选择课程，安排剪辑”** 中填写：

| 字段 | 第一次建议 |
| --- | --- |
| 课程 | 选刚导入的课程 |
| 本计划使用的视频素材 | 勾选本次需要的素材；使用权未知的不要硬选 |
| 计划名称 | “帽子视频—第一次试剪” |
| 剪辑要求 | “约20秒，按教程节奏剪辑，优先帽子细节和上头效果，保留原声” |
| 内容类型 | 商品视频选“商品介绍”；课程演示选“教程讲解” |
| 草稿接收电脑 | A 选“当前服务所在电脑（本地使用）”；B 选已配对的自己的 Mac |
| 用于商业视频 | 首轮个人学习不勾；勾选后只能使用商用已授权素材 |
| 允许发送到已配置云服务 | 零 Key 首轮不勾；需要云能力先看第七节 |
| 每天自动生成一条 | **首轮不要勾选** |
| 每日时间与时区 | 按实际所在地设置，中国与日本时间相差一小时 |

点 **“保存剪辑计划”**。要求文本不代表所有编辑指令都能精确执行，结果必须核对。

### 3. 立即生成

1. 在 **“3. 执行记录与成片”** 找到该计划。
2. 点 **“立即生成（当日一次）”**。
3. 等待“已排队”变成“学习教程 / 剪辑中”。关闭网页不会取消已接收任务。
4. 没有配方先学习；已有配方复用最新配方，不会每次重新听完整课程。
5. 完成后点 **“查看成片与证据”**。

同一计划按所选时区每天最多执行一次，手动和定时共用限制；反复点按钮不是重试办法。需要改要求重做时，新建不同名称计划并暂停旧计划。再次云端执行可能再次收费。

### 4. 真正要验收什么

- 播放 MP4，而不是只看封面：画面有变化、顺序合理，没有明显黑场；音频与字幕符合预期。
- 教学分段是否区分讲解、软件操作和成片示例。
- 规则是否来自教程的真实句子与时间段，而不是把示例广告口播当要求。
- 时间线是否有规则关联，镜头、时长、顺序等是否受到影响。
- 质检报告是否有阻断。技术质检通过不等于审美、理解和营销效果优秀。
- 在剪映实际打开轨道，检查媒体/音频/字幕，再手工导出一次短片播放。

课程理解当前是 ASR、OCR、画面特征与规则分类的组合，不保证理解任何复杂网课。画中画、边操作边讲解、示例快速穿插更需要核对。

没有样本时可在“配置助手 → 运行完整教学演示”做辅助验证，但演示课不等于你的付费课程；首次可能下载模型和演示素材，不能冒充真实钉钉链路验收。

## 五、如何进入剪映，ZIP 是什么

### 本地 A

先打开剪映创建过空草稿。课程任务通过质检后会尝试本地交付；已有成功状态不必重复导入。若只有成片，在结果页找 **“导入剪映并打开”**，观察交付状态，再到剪映首页查看新草稿。程序只创建新工程，不覆盖旧草稿。

### 服务器 B

服务器先生成包，由 Mac 助手下载、验证、复制媒体并回报。计划要选对自己的 Mac；服务器的“当前服务所在电脑”不是你的 Mac。

| 状态 | 意思和操作 |
| --- | --- |
| 已排队 | 等待执行；若页面提示调度器关闭，请管理员启用 |
| 学习教程 / 剪辑中 | 正在处理；长期不变要看日志 |
| 成片已完成，等待电脑接收 | 检查目标 Mac 登录、联网与助手运行状态 |
| 助手已确认写入剪映草稿 | 文件交付已回报，仍需在该版本剪映里实际打开 |
| 草稿接收失败 | 查权限、目录、空间、连接错误 |
| 质检未通过，未投递 | 先检查报告和素材，不绕过门禁 |
| 服务曾中断 | 不自动重跑，先检查已有输出再决定恢复 |

`preview.mp4` 是成片；`draft.zip` 是包含轨道与媒体的传输/恢复包。**不要把 ZIP 当视频拖进剪映，也不要只解压就断言已经导入。**助手负责路径和媒体校验。草稿交付不等于自动点击剪映导出，更不等于已发布抖音。

常见检测位置有 `/Applications/JianyingPro.app` 和 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`，但版本、安装方式可能不同。先保留默认目录；识别失败时提供非敏感路径给维护者，不要往猜测的目录搬工程，也不要寻找并不存在的通用文件夹选择按钮。

## 六、B 路线：服务器就绪后安装 Mac 助手

### B1. 管理员先提供

1. 真正可访问的 HTTPS 网址及访问方法。
2. 已开通的云服务、额度和费用承担方式。
3. 匹配 Mac 芯片、来源可信的安装包及签名/公证/实机验证状态。
4. 可生成设备配对码的管理员。

缺少这些就先不安装。助手不会购买服务器或自动把代码部署到云端。当前是受控单工作区，不是已验证租户隔离的公共多人 SaaS。

### B2. 安装和配对步骤

1. 从管理员正式渠道或[项目 Releases](https://github.com/BreetyGreen/video-workbench/releases)获取 `VideoWorkbench-Sync-Setup-macOS.zip`。
2. 没有正式发布条目就说明没有公开安装版。Actions 附件只是开发验收构建，不代表已签名。
3. 解压得到 `VideoWorkbench Sync Setup.app`，确认来源、架构和安全状态后运行。
4. 填真实 **HTTPS 服务器地址**，不要包含用户名、密码、配对码或查询参数。
5. 管理员在该服务器“配置助手 → 服务器交付”点 **“生成 10 分钟配对码”**。
6. 在设置窗口输入一次性码。它只使用一次，过期需新生成，不要截图公开。
7. 只有出现“设置完成”才算配对和自动启动注册成功；关闭窗口或报错不能算成功。
8. 返回课程页刷新，在“草稿接收电脑”选自己的设备；让管理员核对，不凭相似名字猜选。
9. 手动生成一次，验证等待接收、写入草稿、实际剪映轨道，最后才开启每日计划。

助手安装到 `~/Applications/VideoWorkbenchSync`，数据在 `~/Library/Application Support/VideoWorkbench Sync`，用当前用户 LaunchAgent 登录后运行。运行助手本身不要求用户另装 Python、clone 仓库或让 Codex 常驻。

### B3. 安全与权限

未签名开发包可能出现未知开发者或无法验证提示。**不要关闭 Gatekeeper、SIP，或运行批量移除隔离属性命令。**让维护者提供匹配架构的可信签名公证包；提示损坏或恶意软件时停止。判断参考 [Apple 官方安全打开 App 说明](https://support.apple.com/zh-cn/102445)。

只授权确实需要的文件夹/后台运行能力，不把“完全磁盘访问”当默认要求。安装、登录自启、系统权限和当前剪映版本必须在真实 Mac 上验收。

## 七、Key 怎么配置，哪些会收费

| 需求 | 需要什么 | 未配置时 |
| --- | --- | --- |
| 本地上传、分析、剪辑、原声、草稿 | 本地工具和模型，无云 Key | 可用本地模式 |
| BigASR 云转写 | 语音 API Key 或 App Key + Access Key、资源 ID、任务云同意 | 本地 Whisper |
| TTS 云旁白 | 有权限的 Key、资源 ID、官方音色 ID、任务云同意 | 保留原声，不承诺有旁白 |
| Dify 增强 | 服务地址、对应工作流 Key | 本地策略；Dify不是剪辑器 |
| Pexels/Pixabay 素材搜索 | 相应平台 Key | 手工上传授权素材 |
| Seedance 生成新素材 | 方舟 Key、开通的模型端点 | 不自动生成新视频 |
| 官方余额/用量 | 专用只读 IAM AK/SK | 本地累计，不代表官方余量 |
| 钉钉接收课程 | 组织应用、Stream 授权和运行中的连接器 | 手工上传 |

设计的图形入口是“配置助手 → 填写增强服务配置”（`/settings/providers`），在对应卡片填写、点“加密保存”，按提示重启。已保存字段留空表示保持不变；字段齐全不等于权限与真实调用已经通过。

**本版本已知问题：**该页模板引用 `provider-settings.js` / `provider-settings.css`，实际文件为 `provider_settings.js` / `provider_settings.css`，存在 404 风险，可能始终显示加载。此问题本次只记录，未修改程序。没有出现卡片时，不要反复填写、更不要发 Key 给别人；继续零 Key 模式，让维护者修复并验证后再配置。本手册不把此页面称为已验收可用。

官方用量另在 `/settings/cloud-usage`；只读 AK/SK 与推理 Key 用途不同。Mac 脚本不会主动读取仓库根 `.env`；另一个受支持途径是维护者指导在启动进程环境里配置变量。不要随意建 `.env`、把秘密写进命令历史，或复制作者 Windows 的密钥。

B 的云配置由管理员在服务器统一完成，不要求每个 Mac 用户重复填写。任务允许云处理会发送相关音频/文字并可能收费；有赠送额度不代表永远免费。

钉钉里能看到网课不等于机器人有下载权限；没取得组织和文件授权时，通过平台允许的方式下载有权处理的文件再手工上传。不能只粘贴网盘链接就算已接入。

## 八、日常运行、更新与备份

### 每日自动生成

先完成一次手动全流程验收，再在计划中开启每日执行。已有计划上的“开启每日执行”使用该计划保存的时间。

- A：Mac 开机、登录、不休眠，本地服务在运行。bootstrap 不等于后端开机自启；重启电脑后需要重新启动服务。
- B：服务器持续运行；Mac 离线可等待接收，登录联网且助手运行后再同步。睡眠/退出登录时不保证接收。
- 同日手动运行过，不会再次定时运行。暂停不取消已排队任务，停机不追补所有历史日期。
- 改课程、素材、要求、时间或设备时，新建计划并暂停旧计划。
- 当前复用固定素材，不承诺自动添新素材或每日成片不同。
- 课程计划与首页旧的热点/关键词自动化不同，不要同时开启两条路径测试同一任务。

### 第二天启动 A

```bash
cd "$HOME/Projects/video-workbench"
bash scripts/start-local.sh
```

缺工具则再跑 bootstrap。试用时建议保留终端，不把关终端或睡眠后的进程存活当成保证。

### 停止 A

先暂停不需要的计划、等待当前任务结束，再运行：

```bash
cd "$HOME/Projects/video-workbench"
bash scripts/stop-local.sh
```

此脚本停止控制面，不等于卸载剪映或停止所有独立助手。停止失败时保留日志，别随意杀所有 Python 进程。

### 更新 A

没有任务执行时停止服务、备份数据，再检查：

```bash
cd "$HOME/Projects/video-workbench"
git status --short
```

仅当输出为空且确认没有自己的代码改动时，执行：

```bash
git pull --ff-only
bash scripts/bootstrap.sh
```

有修改、分支分叉或拉取失败就停下找维护者。不要 `git reset --hard`，不要为更新删除运行数据。

### 文件位置和备份

Finder 按 `Command + Shift + G` 输入路径查看：

| 路径 | 内容 |
| --- | --- |
| `~/Projects/video-workbench` | 代码，不是成片数据目录 |
| `~/Library/Application Support/VideoWorkbench` | 数据库、课程、任务、成片、加密密钥材料，需要整体保护 |
| `~/Library/Application Support/VideoWorkbench/models` | 当前分析代码实际使用的 Whisper 模型目录 |

| `~/Library/Application Support/VideoWorkbench Sync` | B 助手凭据、日志与状态 |
| 剪映实际草稿目录 | 工程及媒体副本，单独保护，别随意移动引用素材 |

停止任务和服务后，使用 Finder/受保护备份工具把整个数据目录（包括隐藏文件）复制到新的备份位置。数据库和加密密钥要一起保护，不可只留数据库又删除密钥。不要把备份上传到公开 GitHub。Mac 助手备份不能代替服务器备份，服务器由管理员负责。

## 九、常见问题与可复制诊断

| 症状 | 先做什么 |
| --- | --- |
| 找不到 `scripts/bootstrap.sh` | 先进入 `~/Projects/video-workbench`，确认不是 ZIP 外层目录 |
| `FFmpeg is required` | 完成 Homebrew 官方安装/PATH设置，重跑 bootstrap |
| 找不到 uv | 新开终端重跑 bootstrap，不删除用户目录 |
| 浏览器无法连接 | A先启动再访问8130；B用真实服务器；不要用维护者8177链接 |
| 8130被占用 | 用下面只读命令看进程，不杀不认识的程序 |
| PID仍活着但不健康 | 看日志，启动器为避免重复服务会拒绝再次启动 |
| 首次转写慢或失败 | 查模型下载、网络、空间；先用短教程，不保证固定等待时长 |
| 配置页一直加载 | 第七节所述已知资源路径问题，联系维护者，不暴露Key |
| 计划一直排队 | 看页面是否说调度器关闭；让管理员检查单实例worker |
| `course_recipe_has_no_rules` | 教程规则未提取到，查转写，换短清晰教程或真实TXT讲义 |
| 素材不可用/无授权 | 检查课程归属及个人/商用标记，不能虚报授权 |
| 只有图片/没声音或字幕 | 确认播放MP4而非封面，查源人声与TTS配置 |
| 只有ZIP/剪映没工程 | 查路径、权限和助手，按第五节处理 |
| Mac包打不开/损坏 | 查架构、来源和签名，停止并联系维护者，不关闭安全保护 |
| 配对失败 | 查HTTPS、网络、访问控制、10分钟有效期，获取新的一次性码 |
| 同步HTTP401/403 | 管理员检查设备令牌及代理策略，不把登录密码拼进URL |
| 安装回滚或人工恢复提示 | 不删旧助手与setup-backups；由维护者处理，保留配对状态 |
