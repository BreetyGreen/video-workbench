# 全自动视频生产工作台设计

## 目标

在 Windows 本地运行一个有界面的短视频生产系统，覆盖：素材入站、教程解析、热点与爆款分析、剪辑计划、剪映草稿、MP4 预览、文案话题、人工审核和受控发布。第一原则是可审核和可恢复，不把未验证的浏览器自动发布伪装成官方能力。

## 已确认架构

```text
钉钉/本地素材/教程/热点
          │
          ▼
   本地任务中枢 ─────► Dify：教程、爆款、脚本、文案与话题
          │
          ▼
 ArcReel：项目、素材、分镜、生成、成本与人工修改
          │
          ├────► pyJianYingDraft：可编辑剪映草稿
          ├────► FFmpeg：MP4 预览与机械质检
          └────► 审核包：草稿、成片、封面、文案、话题、风险
                                  │
                                  ▼
                              人工确认
```

ArcReel 是用户日常看到的视频生产工作台；Dify 是可替换的 AI 分析服务；`pyJianYingDraft` 是剪映草稿核心；CapCut Mate 只在需要 HTTP 工作流调用时提供 API 包装。Dify、ArcReel 和剪映适配器不能直接共享大视频文件，任务中枢使用本地绝对路径或受控下载 URL 传递素材引用。

## 用户流程

1. 用户在本地控制台新建任务，或由钉钉机器人创建任务。
2. 系统保存素材、来源、哈希、授权声明和教程引用。
3. Dify 将教程编译为版本化的 `edit_recipe.json`，同时输出热点匹配、脚本、文案和话题。
4. ArcReel 管理项目、分镜、素材生成和人工修改。
5. 剪辑适配器生成剪映草稿；FFmpeg 生成独立 MP4 预览。
6. 系统汇总审核包。审核人可以批准、退回或重新生成单一步骤。
7. 批准后只进入“待发布”状态；抖音官方授权未配置时不执行发布。

## 状态模型

任务状态固定为：

```text
received -> analyzing -> planning -> editing -> reviewing -> approved -> delivered
                              \-> failed
reviewing -> changes_requested -> planning
```

每一次状态变化都记录时间、操作者、输入摘要、输出文件和失败原因。重试以步骤为单位，不能在失败后自动重复发布。

## 组件边界

### ArcReel

- 使用固定 Docker 镜像版本，持久化 `projects`、`logs` 和配置。
- 负责可视化项目、素材、分镜和剪映草稿导出。
- 不直接保存钉钉密钥或抖音 Cookie。

### 本地任务中枢

- FastAPI 服务，保存 SQLite 任务数据库和本地素材目录。
- 提供健康检查、任务创建、任务查询、步骤重试和审核接口。
- 所有文件名都重新生成，原始文件名只作为元数据保存。
- 只允许访问任务根目录内的素材，不接受任意本地路径。

### Dify

- 使用可导入导出的 DSL 管理两个工作流：`tutorial-analysis` 和 `viral-analysis`。
- 输入为文本、小型图片或任务中枢签发的文件 URL；大视频先抽帧和转写。
- 输出必须匹配 JSON Schema；无法解析时任务失败并保留原始响应。

### 剪映与 FFmpeg

- `pyJianYingDraft` 生成草稿；第一阶段只保证草稿在当前官方剪映中可见和可打开。
- 剪映 7+ 不承诺无人导出。MP4 预览由 FFmpeg 独立生成。
- 未检测到剪映时，草稿仍可生成，但任务标记为“未做剪映打开验证”。

### 钉钉和抖音

- 钉钉使用官方 Stream SDK，文件下载后进入同一个任务创建接口。
- 抖音只使用官方授权能力或移动分享流程；未配置时只生成待发布包。
- 浏览器 Cookie 自动发布不进入第一版生产路径。

## 安全与合规

- API Key、AppSecret、OAuth token 仅从环境变量读取，不写入仓库和任务日志。
- 素材必须记录版权/授权状态；未确认授权的任务不能进入 `approved`。
- AIGC 内容在审核包中包含声明字段。
- 医疗、法律、财经和新闻内容默认要求额外人工审核。
- 外部下载限制协议、大小、重定向次数和目标地址，禁止访问回环与内网保留地址。

## 第一阶段完成标准

1. `http://localhost:1241` 可打开 ArcReel 并通过健康检查。
2. 任务中枢能创建任务、保存素材、查询状态并输出审核包清单。
3. Dify 工作流 DSL 可导入，未配置模型时显示明确错误。
4. 至少一个样例任务能生成 MP4 预览和剪映草稿文件夹/ZIP。
5. 钉钉连接器有真实官方 SDK 入口；缺少凭据时健康检查为 `not_configured`。
6. 一条命令可运行自动测试和本地服务健康检查。
