# GitHub + Codex macOS 零配置本地视频工作台设计

日期：2026-08-21
状态：待用户书面确认
首发平台：macOS（Apple Silicon 优先，Intel 兼容）

## 1. 目标

用户从 GitHub clone 仓库后，不编辑 `.env`、不安装 Docker，也不手工填写剪映路径。用户只需在仓库中告诉 Codex“启动项目”，Codex 按仓库内 `AGENTS.md` 执行统一入口，完成环境诊断、依赖安装、素材库初始化、服务启动和剪映检测。任务生成后保留机器质量门禁，取消人工批准步骤；通过门禁的草稿自动导入本机剪映。

成功标准：一台全新的 Apple Silicon Mac 在 clone 后可以仅通过 Codex 完成首次启动；除 macOS 系统权限、可选文件夹选择和官方账号登录外，不要求用户复制 Key、编辑配置文件或理解运行命令。

## 2. 非目标与边界

- 不部署公开网站，不要求云服务器。
- 不把任何平台密钥、登录态或用户素材提交到 GitHub。
- 不绕过平台登录、接口签名或风控；商家素材通过用户主动下载/导出、网盘包、本地文件夹和明确允许下载的公开文件进入素材库。
- 首版不要求抖音发布审批完成；审批通过后使用官方 OAuth，并做成点击授权而不是配置表单。
- 不承诺在 CI 中启动真实剪映；CI 使用目录夹具验证检测和安全导入，真实剪映兼容性在 Mac 验收机完成。

## 3. 用户流程

1. 用户执行 `git clone`，在 Codex 中打开仓库并说“启动项目”。
2. Codex 读取通用化后的 `AGENTS.md`，运行 `scripts/bootstrap.sh`。
3. 启动器识别 `arm64`/`x86_64`、macOS 版本、可用磁盘和网络；安装或复用固定版本 `uv`，由 `uv` 管理 Python 3.12 与项目虚拟环境。
4. 启动器检测 `ffmpeg`/`ffprobe`。已存在则复用；缺失时优先通过 Homebrew 安装。需要系统确认时只触发系统提示，不要求填写项目配置。
5. Apple Silicon 默认使用 MLX Whisper；不可用或 Intel Mac 回退到现有本地转写适配器。macOS 本地旁白优先使用系统 `say`，再由 FFmpeg 转换为时间线音频。
6. 首次运行在 `~/Library/Application Support/VideoWorkbench` 创建数据库、素材库、任务产物和自动生成的本机配置，在 `~/Library/Caches/VideoWorkbench` 保存可重新下载的模型缓存。
7. 创建 `~/Movies/VideoWorkbench Inbox` 作为零配置素材入口并开始监听。用户也可以拖拽视频或通过 macOS 文件夹选择器增加观察目录；选择结果自动保存。
8. 启动本地回环控制台。任务完成并通过质量门禁后，系统自动发现剪映草稿目录、安全导入新草稿并尝试打开剪映。

## 4. 启动与依赖架构

### 4.1 统一入口

- `scripts/bootstrap.sh`：macOS 首次安装和幂等升级入口。
- `scripts/doctor.py --json`：只读诊断操作系统、CPU、Python、FFmpeg、模型、数据目录、端口、剪映安装和草稿目录。
- `scripts/start-local.sh`：启动本地 FastAPI 控制面和文件夹监听器，写入 PID/日志，不依赖 Docker。
- `scripts/stop-local.sh`：只停止本项目记录的 PID，不扫描或终止其他 Python/FFmpeg 进程。
- `scripts/bootstrap.ps1`、`start-local.ps1`：复用相同的 Python doctor 协议，为 Windows 后续实现保留一致接口。

`AGENTS.md` 不再包含开发者机器的 `B:` 盘路径，只描述相对路径、入口命令、验证方式和安全规则。Codex 应先运行 doctor，再根据结构化结果执行恢复；不得要求用户手工拼接命令。

### 4.2 零配置原则

- 必需运行参数全部有本地安全默认值并在首次启动生成。
- 云端 Dify、火山、Pexels、Pixabay、Seedance 和抖音凭据全部是增强项；缺失时不能阻断本地主链。
- 不显示空白配置表单。后续接入官方服务时使用 OAuth、macOS Keychain 或系统文件选择器。
- 自动生成的配置和数据位于用户 Library，仓库只保存无秘密的示例与 schema。
- 首次模型下载显示进度、大小和可取消状态；失败时允许再次运行同一入口恢复。

## 5. 素材来源与沉淀

### 5.1 零配置来源

- 自动创建并监听 `VideoWorkbench Inbox`。
- 控制台支持拖拽和批量选择文件/文件夹。
- 支持商家主动导出的 MP4/MOV、ZIP 资料包、网盘同步目录和用户浏览器下载目录。
- 对用户明确确认可使用的直链文件提供“导入链接”；不处理要求破解登录或签名的地址。
- 每次导入记录来源、原始文件名、导入时间、授权依据和允许平台；无授权状态的素材只能进入隔离区，不能自动剪辑。

### 5.2 素材资产引擎

入库按以下顺序执行：

1. SHA-256 精确去重、媒体探测和损坏文件隔离。
2. 镜头切分与关键帧抽取，保存镜头时间范围而不是复制整段视频。
3. OCR、语音转写、人物检测（只检测人物，不默认识别身份）、商品主体和场景分类。
4. 自动标签与可修改标签，生成镜头级文本描述。
5. 视觉/文本向量索引，实现自然语言搜索。
6. 感知哈希与向量相似度结合，识别转码、裁剪或轻微修改后的近似素材。
7. 记录素材、镜头和成片之间的使用关系、使用次数、最近使用和质量反馈，减少重复选镜头。

目录监听只处理新增或变更文件；使用稳定文件等待、任务队列和内容哈希保证重启后不会重复导入。删除源文件不会自动删除素材库副本，清理由用户显式执行。

## 6. 自动质量门禁与剪映交付

主状态流调整为：

`queued → analyzing → editing → quality_check → importing → imported`

异常状态为 `needs_attention` 或 `failed`。不再要求 `approved`/`changes_requested` 才能导入剪映。

- 阻断检查：缺视频/音频、无法解码、时间线断裂、黑屏、关键素材丢失、字幕/旁白文件缺失、草稿结构无效、媒体路径不存在。
- 警告检查：节奏偏慢、字幕密度偏高、轻微静音等。只有警告时允许自动导入，并在任务详情中展示。
- 阻断失败先执行最多两轮确定性修复；仍失败则保留全部产物和诊断，状态设为 `needs_attention`，绝不导入坏草稿。
- 原审核页改为“任务结果与诊断”，保留预览、质量报告、文案和日志，但移除批准/驳回按钮与审核事件依赖。

## 7. macOS 剪映发现与安全导入

检测顺序：

1. 读取已验证且仍存在的本机配置。
2. 使用 `mdfind` 和 `/Applications`、`~/Applications` 查找剪映/CapCut 应用包。
3. 在 `~/Movies`、`~/Documents` 和 `~/Library/Application Support` 的有限候选目录中查找 `com.lveditor.draft` 或含有效 `draft_info.json` 的草稿根；不遍历整个磁盘。
4. 多个候选根据有效草稿结构、最近修改时间和应用关联评分。只有无法唯一确定时调用 `osascript` 弹出文件夹选择器一次。
5. 验证目标存在、可写且不是符号链接逃逸路径，随后把确认结果保存到本机配置。

导入时先在本项目 staging 目录解压和重写 macOS 绝对媒体路径，逐条验证媒体存在，再以唯一草稿名原子移动到目标目录。目标同名时生成新后缀，不覆盖、不扫描和不改写其他剪映草稿。导入完成后使用发现到的应用包路径打开剪映；打开失败不撤销已验证的草稿。

## 8. 错误处理与恢复

- bootstrap 每一步输出结构化状态并保持幂等；重复运行只修复缺失项。
- 依赖下载使用固定版本、HTTPS 和校验值；下载中断保留可恢复缓存或安全清理单个临时文件。
- 数据库迁移前创建可验证备份；失败时不启动新版本服务。
- 文件监听和分析任务持久化，异常退出后从未完成步骤继续。
- 端口冲突自动选择可用回环端口并保存；不监听公网地址。
- 所有日志掩码处理密钥、令牌和用户主目录中的敏感片段。

- Windows 现有 148 项控制面测试和 7 项连接器测试继续保留。
- 新增 macOS doctor、路径发现、配置生成、监听去重、自动门禁和安全导入单元测试。

- 所有脚本执行 ShellCheck；Python、JavaScript、数据库迁移和草稿 ZIP 结构继续验证。

### 真实 Mac 验收

1. 在一台 Apple Silicon Mac clone 仓库。
2. 只向 Codex发送“启动项目”，不手工编辑文件。
3. 控制台成功打开，Inbox 和本地数据目录自动创建。
4. 放入三条视频，系统批量导入并完成去重、镜头切分、标签和搜索。
5. 创建任务后无人工审核步骤；质量通过后草稿自动进入该 Mac 的剪映并可正常打开。
6. 重启 Mac 后再次启动，素材、索引、草稿路径和未完成任务均可恢复。
