# 自适应原声与豆包旁白设计

## 目标

让每个视频任务自动选择原声、混合旁白或纯旁白，并在需要旁白时调用火山引擎豆包 TTS 2.0。系统不得为了“有配音”而覆盖可用的人声，也不得在 TTS 失败时阻断视频剪辑。

## 默认决策

- `original`：选中片段中存在清晰转写内容，且有效人声覆盖达到阈值。保留原声并使用原转写字幕，不调用 TTS。
- `mixed`：存在少量有效人声或关键宠物声音，但不足以构成完整叙事。保留原声，生成短旁白；旁白出现时原声自动降低。
- `narration`：没有有效人声，或素材只有环境声/杂乱库存音频。生成完整旁白，原音降低为氛围层。
- TTS 未配置或调用失败：保留原声/静音轨继续渲染，在审核清单记录明确警告，不伪装为已配音。

## 旁白来源与音色

- 服务：火山引擎豆包语音合成模型 2.0。
- 接口：`POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`。
- 鉴权：优先复用新版豆包语音 API Key；密钥仅从本地环境变量读取。
- 默认音色：`zh_female_vv_uranus_bigtts`，默认资源 `seed-tts-2.0`，采样率 24 kHz，MP3。
- 默认语气：自然、亲切、克制，宠物内容不使用夸张幼态腔。
- 旁白文本：优先使用 Dify 教程分析返回的 `voiceover_script`；没有教程或 Dify 失败时，根据任务标题、类目与制作要求生成简短本地基线，不编造素材中不存在的事实。

## 组件边界

1. `VolcanoTTSClient` 只负责鉴权、请求、增量解析响应和写入音频文件。
2. `AudioRoutingService` 只根据分析结果与旁白文本生成可审计的音频决策。
3. `TimelinePlanner` 接收已确定的音频决策，把旁白路径、模式、增益和旁白字幕写入统一时间线。
4. `RenderService` 分别混合原声、旁白和背景音乐；原声增益由模式决定，旁白作为主声音轨。
5. `PipelineService` 负责串联并把音频决策、音色、失败原因写入 `review.json`。

## 数据与审核

`AudioMixPlan` 新增 `mode`、`voiceover_path`、`voiceover_gain_db`、`voice_type` 和 `decision_reason`。审核清单展示实际模式、是否调用 TTS、具体音色与降级原因。TTS 音频保存在任务产物目录，不写入仓库。

## 验证

- 单元测试覆盖三种路由、TTS 流式 JSON 解析、未授权降级和渲染器输入图。
- 集成测试覆盖无转写库存素材生成旁白、有人声素材不调用 TTS，以及审核清单可追踪。
- 全量控制面测试、真实 TTS 权限探测、端到端宠物素材样片和早/中/晚画面抽检必须通过。
