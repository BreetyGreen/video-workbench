# 首次启动与连接配置向导设计

日期：2026-08-21

## 目标

让从 GitHub 克隆项目的普通用户在不填写 `.env`、不理解 API 名称的情况下立即使用本地视频生产主链，并在需要云端、素材或发布能力时，由应用内向导完成申请、录入、验证和故障定位。

成功标准：

1. 全新克隆启动后，用户首先看到可理解的环境检查结果，而不是技术配置表。
2. FFmpeg、本地数据目录、素材收件箱和剪映位置由系统自动发现；本地模式可直接进入工作台。
3. 外部能力以“可选增强”展示，未配置不得阻塞本地上传、分析、剪辑、字幕、预览和剪映草稿生成。
4. 每个外部能力都提供用途、是否必须、官方申请入口、最小字段、连接验证和明确的权限错误。
5. 凭据不进入 Git、页面读取响应或日志，只保存在本机加密存储中。
6. 用户可随时从工作台重新进入向导，查看配置完成度并重新验证。

## 方案选择

采用“本地模式立即可用 + 应用内渐进式连接向导”。不采用纯文档引导，因为它无法给出实时检测和精确错误；不采用统一托管账号，因为那会引入凭据托管、计费和多租户安全责任。

## 信息架构

新增 `/setup` 首次启动向导，由四个连续步骤组成：

1. **本机检查**：平台、架构、FFmpeg/FFprobe、本地运行目录、素材收件箱、剪映安装和草稿目录。
2. **本地模式就绪**：明确列出无需账号即可使用的能力，提供“立即进入工作台”。
3. **连接增强能力**：以卡片展示火山引擎、免费素材库、抖音开放平台和钉钉；用户按需展开配置。
4. **验收结果**：重新汇总本地能力与外部连接状态，提供最小样例流程说明和工作台入口。

工作台连接状态区增加“配置助手”入口和配置完成度。首次启动是否自动进入 `/setup` 由本机状态决定：尚未确认本地模式时自动跳转；确认后不再强制跳转。用户可以跳过所有外部连接。

## 组件与边界

### SetupService

单独的服务层负责生成配置清单，不在路由或前端复制判断逻辑。它聚合：

- 本机运行状态；
- 现有 `/api/integrations/status` 连接状态；
- 素材提供方状态；
- 已完成步骤和本地模式确认状态。

该服务只返回掩码、布尔状态、用户可理解的提示和官方链接，不返回秘密值。

### Setup API

- `GET /api/setup/status`：返回总体状态、步骤、能力卡片和完成度。
- `PUT /api/setup/preferences`：保存“本地模式已确认”和“稍后配置”等非敏感偏好。
- `POST /api/setup/validate/{provider}`：验证指定提供方，返回稳定错误码与修复建议。

本阶段复用已有云端余量安全存储；其他提供方只在已有安全写入能力存在时开放表单。尚未实现安全写入的提供方显示官方申请入口、字段清单和配置方式，但不得把明文凭据存入浏览器存储。

### Setup UI

新增独立模板、CSS 和 JavaScript。界面复用现有设计系统和导航，不引入前端框架。所有状态均有文字，不仅依赖颜色；手机端使用单列卡片，桌面端使用两列连接卡片。

## 数据流

1. 启动脚本完成依赖和目录准备并启动 FastAPI。
2. 浏览器访问 `/`，服务端检查是否完成首次本地确认；未确认则跳转 `/setup`。
3. 向导请求 `/api/setup/status`，服务端实时聚合本机与连接状态。
4. 用户可以立即确认本地模式并进入工作台，也可以打开任一增强能力的配置说明。
5. 验证请求只访问所选提供方，返回 `configured`、`partially_configured`、`not_configured`、`permission_required` 或 `unreachable`。
6. 工作台再次读取 setup 状态，展示完成度及下一项建议。

## 外部能力指引

每张卡片必须包含统一结构：

- 能力名称与实际收益；
- 本地模式是否有替代方案；
- 官方申请页面；
- 需要的字段和权限范围；
- 安全提示；
- 当前诊断、验证按钮与下一步。

提供方范围：

- **火山引擎**：方舟模型、ASR/TTS、只读用量分别说明，不误导用户共用一种凭据。
- **素材库**：Pexels、Pixabay 分开说明；未配置时回退用户上传和本地授权素材。
- **抖音开放平台**：说明应用审批和用户 OAuth，不承诺不存在的客户端草稿箱 API。
- **钉钉**：说明 Stream 应用与组织授权；未配置不影响本地上传。

## 错误处理

- 命令或目录缺失：显示系统检测事实和可执行修复动作。
- 字段缺失：指出字段名称，不显示或回传其他字段内容。
- 凭据无效：显示“凭据未通过验证”，不回显服务端原始鉴权响应中的秘密信息。
- 权限不足：显示具体缺少的权限或审批步骤。
- 网络不可达：保留本地模式可用状态，并允许稍后重试。
- 第三方接口异常：不把异常等同于余额为零或配置成功。

## 测试与验收

采用测试先行：

1. 服务测试证明全新状态默认可进入本地模式、外部能力均为可选。
2. API 测试证明状态响应不包含凭据，并能保存首次本地确认。
3. 路由测试证明未确认时 `/` 跳转 `/setup`，确认后返回工作台。
4. 提供方验证测试覆盖未配置、部分配置、权限不足和成功。
5. JavaScript 语法检查和桌面/手机浏览器验收覆盖无横向溢出、键盘操作和状态文案。
6. 全新克隆验证器检查启动后 `/setup` 可访问，且无需 `.env` 即可确认本地模式。

## 非目标

- 不把项目维护者的 API Key、Cookie 或 OAuth 令牌放入公开仓库。
- 不绕过第三方登录、应用审批、签名或风控。
- 不在本阶段建设托管账号、统一计费或多租户密钥服务。
- 不强制用户为本地剪辑配置任何云服务。
