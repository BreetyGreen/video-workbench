# 全链路参考驱动的视频生产改造

状态：已批准并分批实施；统一分镜和有界素材视觉输入已进入本地代码，整体新链路真实端到端验收尚未完成。2026-09-08。最新边界见 `docs/progress.md`；下方“当前代码证据”为设计启动时的诊断快照。

## 用户目标

用户交付教程、参考成片和独立的授权素材后，系统能够学习表达与剪辑方法，自动生成针对当前产品的成片，并交付可编辑剪映草稿。普通用户不需要 Codex 常驻，也不需要逐镜头操作。不能把某条人工制作的成功样片视为平台能力。

范围是现有生产链路，不扩展网站重设计、服务器采购、抖音审批、未经授权的数据采集或发布。保留零 Key 的本地基线与现有课程/定时/设备同步入口。

## 当前代码证据

- `services/control-plane/app/services/pipeline_service.py::_narration_text` 仍通过品类关键词返回帽子/宠物梳固定台词，未使用教程、参考片、商品证据生成针对性脚本。
- `services/control-plane/app/services/timeline_service.py` 候选排序主要依赖语音、清晰度/曝光、场景变化和交替来源；缺少逐句文案与镜头语义对应。
- `workflows/dify/tutorial-analysis.yml` 的 `vision.enabled` 为 false；现有画面描述文本不能替代模型实际看到图像。
- `services/control-plane/app/services/tutorial_understanding_service.py` 已保存讲解/软件操作/示例分段与来源位置，但本地启发式分类不等于多模态理解已验证。
- `services/control-plane/app/services/course_recipe_service.py::compare` 根据首尾镜头、平均时长、镜头数变化验证应用规则；变化不等于效果更好。
- `services/control-plane/app/services/quality_gate_service.py` 包含技术质量检查，不能由技术通过推断内容吸引力、卖点真实性或参考风格符合度。
- 2026-09-08 绿豆沙交付为任务专用脚本结果，记录 `production_workflow_modified=false`，不是网站统一链路产物。

## 路线选择

1. **推荐：现有系统增加统一导演计划与证据链。** 保留已有任务、转写、渲染、草稿、同步能力，修正理解、规划、选镜与验收之间的接口。
2. 只升级提示词/增加品类模板：成本低，但解决不了模型看不到画面、文案未进入选镜及错误质量结论。
3. 整套重写：迁移和回归风险大，本次不采用。

## 统一流程与产物

`课程/参考/素材入库 → 多模态证据 → 可复用风格规则 + 商品事实 → 导演分镜计划 → 配音对齐与镜头匹配 → 渲染 → 分层质检与有限返工 → 剪映交付`

### 1. 输入分工

- 教程：学习讲解中的方法，保留课程 ID、版本和原文时间码。
- 参考成片：提取钩子、信息密度、镜头功能、节奏、字幕位置和声音结构；不自动继承其中的商品卖点、价格或广告语。
- 授权素材：最终画面来源；镜头片段需有来源文件、时间范围、权利状态。
- 商品事实：用户提供或包装中可核验的事实，单独维护来源与置信度；OCR 或模型猜测不能直接成为已核实的卖点。

### 2. 学习层

- 联合完整转写、时间戳、场景边界及有覆盖说明的抽样图像，区分老师讲解、剪辑界面、示例成片与未知片段。
- 已配置且获逐任务同意时，通过受支持的服务接口传实际图像，不依赖 Dify 内部数据库或容器内部模型调用作为生产方案。
- 规则保存：适用品类、表达目的、时间码证据、镜头/音频/字幕要求、禁止事项、置信度、分析模式。
- 同一课程通过文件哈希与分析版本缓存；参数或模型改变后创建新版本，不覆盖历史规则。
- 无云权限或额度受限时保留本地分析，并明确标记部分理解；未知画面不补写成确定结论。

### 3. 镜头级素材库

- 建立主体/产品、动作、景别、场景、画面质量、文本区域和音频标签。
- 每个标签关联具体帧或时间段与分析来源。文件夹名仅用于搜索提示，不作为口味、品牌或功效事实。
- 区分同文件重用、同一时间段重用和相似画面；跨商品隔离，缺少合适镜头时报告缺口，不从别的商品凑时长。
- 缓存元数据与语义分析，新增素材只处理增量；模型调用数、字符/秒数及失败记录进入统一用量账本。

### 4. 导演计划：文案与画面一体生成

- 一个版本化计划同时约束脚本、镜头、声音、字幕和交付；TTS、选镜、预览与剪映不得各自另生成内容。
- 每个节拍包含：表达目的、旁白、已核实事实引用、镜头需求、选中素材时间段、选择理由、目标时长、字幕位置、声音意图和参考规则引用。
- 商品视频默认采用使用场景/问题、商品识别、特点与证据、使用场景、结尾引导；实际结构应服从参考与课程，而非所有品类套同一模板。
- 教学视频可使用步骤式叙事；不能误把带货片全部写成操作说明。
- 全部台词在配音前校验：商品一致、无未证实功效或优惠、不是教程示例广告的照搬、没有空洞动作复述堆积。
- 信息不足时允许生成标明限制的本地预览，不强迫填写长表，也不静默宣称高质量完成。

### 5. 配音、字幕、音效和渲染

- 配音由统一计划生成，并做实际转写对齐；保留词尾、重音和必要停顿，不靠截断句子凑时长。
- 以实际旁白时间调整分镜；字幕使用同一文本与时间戳，避免“声音完整但字幕残缺”或字幕漂移。
- 音色采用已授权声音，参考的是讲解风格而非未经授权克隆具体人物。
- 字幕按画面文本、产品主体与安全区域选择位置；不默认越花哨越好。
- 原声音效仅在合适且授权时保留，BGM/SFX有来源记录、可开关、可编辑；不为每次切镜强加转场音。
- 同一时间线驱动预览与剪映，记录渲染器差异，不把预览声音等同于客户端实际混音。

### 6. 分层验收与有限返工

- 技术检查：解码、源路径、连续性、黑场、响度、字幕边界、旁白完整性。
- 内容检查：主体一致、事实有据、句子和镜头匹配、重复片段、信息覆盖、结尾目的。
- 风格检查：按参考测得的分镜功能、时长分布、字幕和声音结构对比；输出证据与偏差，不用无依据的“96分”。
- `technical_pass`、`content_verified`、`style_reviewed`、`native_playback_verified` 分开保存。尚未分析的指标为 unknown，不能当 pass。
- 可确定修复的问题局部返工，最多两轮；消耗需受任务预算限制。遇到费用上限/鉴权错误停止相关云重试，不切换收费模型规避限额。
- 事实错误、错商品、旁白截断阻止正式自动交付。风格不足可保留预览和诊断，不要求用户逐段审核，但不得标成参考效果验收通过。

### 7. 交付与用户体验

- 沿用课程/参考上传入口与课程计划，默认值尽量自动选择；必要输入限于素材权利、目标商品/目的和已有服务授权。
- 过程展示实际阶段：学习、识别素材、编排、配音、渲染、质检、设备接收；失败时保留进度与原因。
- 交付 MP4、统一计划、证据摘要及可编辑草稿；新建工程，不覆盖旧草稿。设备回报与客户端回放验证仍需区分。
- 人类能力指南、Codex 指南、机器能力清单、页面提示和实际实现一并更新，不能先宣传未完成能力。

## 实施顺序

1. 统一计划契约、商品事实边界与红灯回归测试；替换固定商品旁白路径。
2. 接通教程/参考实际多模态输入及镜头证据缓存，加入云失败/额度熔断与真实使用记录。
3. 计划驱动的语义选镜、配音对齐、字幕与声音编排，接入现有渲染/剪映链路。
4. 分层质量报告、有限返工、课程作业/每日计划入口贯通，以及文档与能力清单更新。
5. 正常用户入口实测与跨产品对照验收；原始片、预览和日志不得提交 Git。

## 验收矩阵

- 至少两个不同产品任务，证明确实不再使用帽子/宠物梳固定话术；同产品有/无参考应能解释实际计划差异。
- 教程包含讲解+软件操作+广告示例，示例广告台词不得混入商品事实或配音。
- 文案每句与具体镜头/时间码对应；素材不够、错商品、重复画面、无事实来源均有可测的失败/降级行为。
- TTS过长、只有部分旁白、字幕超界、云额度不足、无 Key、断点重启均有回归用例。
- 正式流水线从课程入口到草稿交付运行；不以 `.validation` 特制脚本或 mocked provider 代替真实验收。
- 自动测试只证明契约/行为；真实云调用、音视频感知审查、Windows/Mac剪映客户端回放分别记录，未做的不称已通过。
