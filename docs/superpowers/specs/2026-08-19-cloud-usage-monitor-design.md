# 云端余量与逐任务用量监控设计

日期：2026-08-19

## 目标

在现有视频工作台中增加统一的云端用量监控，同时回答两个不同问题：

1. 火山引擎账号当前还有多少可用余额、火山方舟已经使用了多少 Token。
2. 每条视频分别消耗了多少 ASR 时长、TTS 字符、旁白时长和大模型 Token。

官方数据与本地推算必须在界面中明确区分。任何估算值都不得显示为官方余额。

## 方案选择

采用“官方管理面查询 + 本地逐调用账本”的混合方案。

- 官方管理面使用只读 IAM AK/SK 查询费用中心余额及火山方舟推理用量。
- 本地账本在每次 ASR、TTS、Dify 调用边界记录任务级用量，包括调用成功但结果未被采用的消耗。
- 豆包语音资源包在没有稳定公开余量查询接口时，由用户配置资源包总额度，本地账本推算剩余，并标注为“本地估算”。

不采用单纯官方查询，因为它无法稳定归因到单条视频；也不采用单纯本地统计，因为它无法反映账户余额、其他调用方和账单抵扣。

## 凭证与安全

### 本地配置入口

工作台增加“云端用量设置”页面。用户在 `127.0.0.1` 页面中填写 Access Key ID 和 Secret Access Key，也可以通过页面上的“从剪贴板读取”按钮分别导入。

安全要求：

- 密钥不得经过聊天、URL、浏览器 localStorage、前端日志或后端日志。
- 保存接口不得在响应中返回密钥明文。
- 页面再次打开时只显示掩码与“已配置”状态。
- 后端使用现有服务主密钥派生独立加密密钥，以认证加密方式保存凭证；数据库中不得出现明文。
- 保存前先调用只读接口验证凭证和权限；验证失败时不替换当前有效凭证。
- 配置页只允许同源 localhost 请求，并校验 `Origin`/`Host`，避免局域网或跨站页面提交密钥。

### 权限边界

IAM 用户为 `video-usage-monitor`。首期支持两种可审计模式：

- 推荐最小权限：费用中心只读，并仅允许火山方舟 `GetInferenceUsage`。
- 快速启动：费用中心只读加全局 `ReadOnlyAccess`；界面提示权限范围较宽，后续可收窄。

系统不需要购买、充值、删除资源、创建模型、修改 IAM 或管理密钥的权限。

## 数据模型

### CloudCredential

保存一份当前有效的火山引擎管理面凭证：

- `provider`
- `access_key_id_masked`
- `encrypted_access_key_id`
- `encrypted_secret_access_key`
- `permission_mode`
- `verified_at`
- `updated_at`

### UsageEvent

每次外部调用写入一条不可变事件：

- `id`
- `task_id`，允许为空以记录健康检查或人工测试
- `provider`
- `service`：`asr`、`tts`、`dify_tutorial`、`dify_viral`、`ark`
- `metric`：`audio_seconds`、`characters`、`input_tokens`、`output_tokens`、`total_tokens`、`requests`
- `quantity`
- `unit`
- `status`：`succeeded`、`failed`、`succeeded_not_applied`
- `request_id`，若上游提供则记录
- `metadata_json`，仅允许非敏感诊断字段
- `created_at`

事件写入与任务状态解耦：即使 Dify 返回结果解析失败，只要上游工作流已经成功执行，也必须记录 `succeeded_not_applied` 和实际 Token。

### UsageBudget

保存用户为本地估算设置的资源包总量与预警阈值：

- ASR 总秒数
- TTS 总字符数
- 方舟可选月度 Token 预算
- 黄色阈值，默认 20%
- 红色阈值，默认 10%

## 调用采集

### ASR

在 `VolcanoBigASRTranscriber` 调用完成后记录请求数和上游返回的音频时长。失败调用记录请求与失败状态；无法确认是否计费时在元数据中标记 `billing_unknown`。

### TTS

在 `VolcanoTTSClient` 中记录请求数、规范化文本字符数、返回音频时长和 voice type。不得记录完整旁白文本。

### Dify 与火山方舟

扩展 Dify 客户端，保留工作流响应中的 workflow run id、输入 Token、输出 Token、总 Token 和耗时。业务输出解析与用量采集分离，确保解析失败时用量仍然落库。

### 官方汇总

新增火山引擎管理面客户端：

- `QueryBalanceAcct`：读取可用余额、现金余额、冻结金额和欠费金额。
- `GetInferenceUsage`：读取火山方舟按日/小时的输入、输出和总 Token。

官方数据缓存五分钟，避免每次打开页面都触发管理面 API。手动刷新按钮跳过当前缓存，但设置最短刷新间隔以防误点。

## API

- `GET /api/cloud-usage/settings`：返回配置状态、掩码和预算，不返回密钥。
- `PUT /api/cloud-usage/settings`：验证并保存新凭证和预算。
- `POST /api/cloud-usage/verify`：只读验证，不落库。
- `GET /api/cloud-usage/summary`：返回官方余额、官方方舟用量、本地累计、估算余量和数据时间。
- `POST /api/cloud-usage/refresh`：触发一次受限的官方数据刷新。
- `GET /api/tasks/{task_id}/usage`：返回单任务用量事件和汇总。

所有响应都包含 `source` 字段，取值为 `official`、`local_measured` 或 `local_estimated`。

## 界面

### 工作台首页

在现有“连接状态”下方增加“云端余量”区域，包含：

- 火山账户可用余额，官方数据。
- 方舟今日与近 30 天 Token，官方数据。
- ASR 已用时长与预计剩余，本地测量/估算。
- TTS 已用字符与预计剩余，本地测量/估算。
- 无效消耗提示，例如“调用成功但结果未采用”。
- 数据更新时间、刷新按钮和“配置”入口。

卡片颜色只表达阈值，不表达接口健康状态。接口健康用单独状态标签表示，防止把“接口失败”误认为“余额为零”。

### 审核页

新增“本条视频云端消耗”面板，显示：

- ASR 调用次数与秒数。
- TTS 字符数与旁白时长。
- Dify/方舟输入、输出与总 Token。
- 成功、失败和未采用调用。
- 本条视频的估算成本；没有可靠单价时显示用量，不伪造金额。

### 配置页

配置页包含掩码凭证状态、剪贴板导入、连接测试、预算与阈值设置。保存按钮只有在验证通过后才可用。

## 错误处理

- 官方接口不可用：展示最后一次成功快照及时间，并标记“官方数据暂不可用”。
- 权限不足：显示缺少的 Action，不删除当前凭证。
- 密钥失效：显示“凭证需更新”，停止后台刷新，但继续展示本地账本。
- 豆包语音无官方资源包接口：只显示本地估算及直达官方控制台的核对链接。
- 数据库写入失败：不得阻断视频主流程；在任务警告中记录用量账本失败并输出结构化日志，但不记录敏感数据。

## 测试与验收

采用测试驱动开发，至少覆盖：

- 凭证加密后数据库不含明文。
- 配置读取接口永不返回 Secret Access Key。
- 新凭证验证失败时保留旧凭证。
- 火山签名请求的服务、地域、时间和签名头正确。
- 官方数据缓存、手动刷新节流和失败回退。
- ASR、TTS、Dify 成功与失败事件。
- Dify 调用成功但 JSON 解析失败时仍记录 Token。
- 工作台卡片明确展示数据来源和阈值。
- 审核页只统计当前任务。
- 没有配置官方凭证时，本地账本仍可使用。

端到端验收：用户在本地配置页保存只读 AK/SK 后，首页能看到官方余额和方舟用量；重新处理一条视频后，审核页能看到该任务的 ASR、TTS 和 Token 消耗，且与本地事件总和一致。

## 非目标

- 不自动充值、购买资源包或调整配额。
- 不创建或修改 IAM 用户、策略和 Access Key。
- 不把密钥同步到 Dify、剪映、钉钉或任何第三方。
- 不在本阶段修改视频剪辑策略、旁白结构或画面效果；视频效果优化在用量监控交付后单独设计和实施。
