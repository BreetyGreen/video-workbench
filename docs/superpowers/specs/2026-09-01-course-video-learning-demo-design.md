# 教学视频学习到自动剪辑的完整演示设计

日期：2026-09-01

## 目标

给一个没有课程文件、没有素材、没有云端 Key 的新用户提供一键演示，并用可审计证据证明系统完成了以下真实链路：

```text
教学视频
  → 音轨提取与 ASR
  → 教程结构和剪辑规则提取
  → 课程配方持久化
  → 独立原始素材分析
  → 按课程配方选镜头和排时间线
  → 成片、字幕、质量报告和剪映草稿
```

演示不能把预置规则文本伪装成教学视频学习结果，也不能把教学视频本身当作被剪素材。

## 验收边界

演示使用两套物理隔离的输入：

1. **教学视频**：一条带中文讲解声音和画面示意的 MP4。教程教授前三秒钩子、镜头时长、问题—解决方案结构、特写、对比、字幕、声音和行动引导。
2. **原始素材**：若干与教程文件不同的宠物护理真实视频。素材带作者、来源页、许可证和下载校验值。

验收时必须产生：

- 教学视频音轨和 ASR 转写；
- 从转写中提取的结构化课程配方；
- 每条配方规则对应的教学视频时间范围与文本证据；
- 原始素材清单、权利状态和哈希；
- 使用课程配方生成的时间线；
- 时间线片段到课程规则的逐条引用；
- 未加载课程配方的基线时间线；
- 基线和课程增强时间线的可解释差异报告；
- 最终 MP4、ASS/SRT、质量报告、剪映草稿 ZIP；
- 本机存在剪映且草稿目录可写时，安全新建草稿并尝试启动客户端。

只有转写成功、配方证据来自教学视频、增强时间线确实引用该配方且与基线存在预期差异，演示才算通过。

## 教学视频来源

仓库保存中文教程脚本、画面卡片定义和预期教学要点，不保存伪造的 ASR 结果。演示准备阶段将脚本生成有声教学 MP4；验收阶段只把 MP4 交给现有课程入库入口，后续服务不能读取生成脚本。

语音生成按以下顺序选择：

1. 已配置且允许本任务使用的火山引擎 TTS；
2. Windows 系统语音或 macOS `say`；
3. 仓库提供的可重新生成的演示旁白音频。

第三项只作为离线兼容资产，仍需经过视频音轨提取和 ASR，不能直接把原始文案交给配方解析器。ASR 优先使用已配置的火山引擎，未配置时使用本地 Whisper。

## 原始素材来源与授权

真实素材从 Wikimedia Commons 的具体文件页下载。演示清单固定记录：

- 文件页与下载 URL；
- 作者；
- CC0 或允许改编的 Creative Commons 许可证；
- 许可证 URL；
- 下载时间、文件大小和 SHA-256；
- 是否要求署名。

下载前展示来源，下载后验证媒体类型和时长。网络不可用或远端校验失败时，系统生成明确标记为 `synthetic_fallback` 的离线素材；不能把合成素材显示为公共实拍素材。授权记录同时写入任务产物和审核页。

## 课程配方

课程配方保存为版本化 JSON，核心字段包括：

```json
{
  "course_id": "demo-course",
  "tutorial_asset_id": "...",
  "transcript_sha256": "...",
  "rules": [
    {
      "id": "hook-first-3s",
      "kind": "hook",
      "value": {"max_seconds": 3, "intent": "problem_first"},
      "evidence": {
        "start_ms": 12000,
        "end_ms": 18400,
        "text": "前三秒先把用户最痛的画面放出来"
      },
      "confidence": 0.94
    }
  ]
}
```

服务需要拒绝没有教学视频证据、时间范围越界、空文本、未知规则类型或置信度无效的规则。配方解析失败时演示明确失败，不回退到同名固定模板并宣称已经学习成功。

## 规则应用与证明

剪辑引擎接收课程配方作为独立输入。选段和排时间线时，每个受规则影响的决定写入 `rule_trace`：

```json
{
  "segment_id": "segment-01",
  "rule_id": "hook-first-3s",
  "tutorial_start_ms": 12000,
  "decision": "将掉毛特写放在开头 2.6 秒",
  "before": "按素材顺序放置",
  "after": "按问题钩子评分置顶"
}
```

同一批素材还生成一份不加载课程配方的基线时间线。差异报告至少验证钩子位置、平均镜头时长、对比结构和结尾行动引导中的两项发生变化。差异为空、规则没有被引用或引用的规则不存在时，质量门禁阻止交付。

## 用户流程

首次启动页增加非强制入口“运行完整教学演示”。点击后系统自动执行：

1. 检查 FFmpeg、ASR 和运行目录；
2. 准备教学视频；
3. 准备并登记授权素材；
4. 创建演示课程并解析配方；
5. 生成基线与课程增强时间线；
6. 渲染增强成片并执行质量门禁；
7. 展示转写、课程规则、规则应用证据、成片和草稿；
8. 剪映可用时显示“导入并打开”，不可用时保留草稿 ZIP 和明确原因。

用户不需要填写主题、素材、Key 或目录。演示结束后可以删除演示任务，不影响真实素材库。

## 跨平台路径

运行路径不能依赖驱动器号：

- Windows 默认使用 `%LOCALAPPDATA%\VideoWorkbench`；用户明确选择的其他盘符保存为本机设置。
- macOS 使用 `~/Library/Application Support/VideoWorkbench`。
- Linux 服务器使用配置的数据卷路径。
- 素材、模型、转写、任务和草稿包都位于运行数据目录，不写入 Git 工作区。

现有 Windows 安装器的“发现 B 盘就自动优先 B 盘”改为显式可选参数；当前开发机仍可继续使用已经选择的 B 盘目录。剪映应用和草稿目录继续按平台有限候选路径发现，无法唯一确认时只要求选择一次。

## 错误处理

- 教学视频无音轨、ASR 空白或规则证据无效：停止在 `tutorial_learning_failed`。
- 公共素材下载失败：记录原因并使用带明确标签的离线保底素材。
- 授权清单缺失或许可证不允许当前用途：素材不入库。
- 课程配方没有改变时间线：停止在 `course_rules_not_applied`。
- 成片或草稿质量门禁失败：保持 `quality_blocked`，不进入设备队列。
- 未安装剪映：演示仍完成 MP4 和草稿 ZIP，不把“无法打开客户端”误报为剪辑失败。

## 测试策略

实施遵循测试先行：

1. 路径测试证明 Windows 默认不绑定 B 盘，显式选择仍可使用 B 盘；macOS 使用用户 Library。
2. 演示清单测试验证 URL、作者、许可证、哈希和合成回退标记。
3. 教学视频测试证明配方解析器输入来自 ASR 产物而非脚本文本。
4. 配方验证测试覆盖证据越界、空证据、未知规则和无效置信度。
5. 时间线测试证明相同素材在有无课程配方时产生预期差异，并生成有效 `rule_trace`。
6. API 和页面测试覆盖一键启动、进度、失败原因和产物链接。
7. 真实烟测下载或生成教学视频与素材，完成 ASR、规则提取、渲染、质量检查和剪映草稿导入。

## 非目标

- 不用演示证明任意网课都能达到同样理解质量；真实课程仍需后续验收。
- 不绕过钉钉登录或文件权限。
- 不把公共素材授权等同于商家私有素材授权。
- 不要求首次演示配置 Dify、火山引擎、抖音或钉钉 Key。
- 不承诺 Linux 服务器能直接操作用户电脑上的剪映；跨设备仍通过已配对同步助手交付。
